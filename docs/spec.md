# Klassed NEET Adaptive Engine — Technical Spec (v1)

This document is the single source of truth for how the engine works. Every intern should read this fully before writing code. If you think a rule should change, raise it with Pranay before implementing something different — don't silently deviate.

---

## 1. Core Philosophy

- **Topic weightage is fixed.** How much of a paper comes from each topic is decided once (Stage 2) and never changes per student.
- **Difficulty per topic is adaptive.** What changes per student is which difficulty tier (Basic/Medium/Advanced) of questions they get, independently for every topic.
- **v1 is rule-based, not ML.** No neural networks, no training. Promotion/demotion logic is deterministic and explainable. ML (Bayesian Knowledge Tracing) is a planned v2 upgrade once real student data exists.
- **Two independent signals per topic:** accuracy (drives level) and time-ratio (drives a separate "pace" flag). They don't affect each other's logic — level changes only from correctness, pace is tracked only from time.

File: `data/taxonomy/{subject}_taxonomy.json`

```json
{
  "subject": "Biology",
  "topics": [
    {
      "topic_id": "BIO-07",
      "name": "Genetics and Evolution",
      "subtopics": [
        {"subtopic_id": "BIO-07-01", "name": "Mendelian Inheritance"},
        {"subtopic_id": "BIO-07-02", "name": "Molecular Basis of Inheritance"}
      ]
    }
  ]
}
```

Every question references a `topic_id` (or `subtopic_id` if we decide to track at that granularity — TBD, default to topic-level for v1 to keep the state machine simple).

## 3. Question Bank Schema

File: `data/tagged_questions/{subject}_questions.json` — one entry per question:

```json
{
  "question_id": "Q00234",
  "text": "...",
  "options": ["A", "B", "C", "D"],
  "correct_answer": "B",
  "topic_id": "BIO-07-01",
  "difficulty": "medium",
  "years_asked": [2019, 2022],
  "expected_time_seconds": 90,
  "wrong_option_tags": {
    "A": "confuses dominant/recessive terminology",
    "C": "arithmetic error in ratio calculation",
    "D": "misapplies law of independent assortment"
  }
}
```

`difficulty` is one of `"basic" | "medium" | "advanced"`.

`expected_time_seconds` default benchmarks (configurable, not hardcoded in application logic — store in a config file so they can be tuned later):
- Basic: 60s
- Medium: 90s
- Advanced: 120s

Note: some topics (calculation-heavy Physics, for example) may need different benchmarks than these defaults — flag to Pranay if a topic clearly needs an override.

---

## 4. Topic Importance Engine

File: `model/topic_importance.json` — `{topic_id: importance_score}`, normalized to sum to 100 across all topics in a subject.

Formula:
```
importance(topic) = Σ_year [ frequency(topic, year) × recency_weight(year) ]
recency_weight(year) = 0.9 ^ (current_year - year)
```

This score is fixed once computed and only recalculated when new year data is added (not per-student, not per-paper).

## 6. Diagnostic Phase (Papers 1–3)

- Fixed papers, same for every student, not generated by the adaptive engine
- Cover all topics, roughly proportional to importance score
- Mixed difficulty within each topic so we get a real read on starting level
- Every attempt logs `time_taken_seconds` from the start (needed for Stage 8 below)

### Initial state assignment (after diagnostics)

For each `(student, topic)`:
```
accuracy = correct_answers_in_topic / total_questions_in_topic

if accuracy >= 0.7: initial_level = "medium"
elif accuracy >= 0.4: initial_level = "basic"
else: initial_level = "basic", flag_for_extra_support = true
```

---

## 7. State Machine (runs after every paper, per student per topic)

```
ON new_answer(student_id, topic_id, is_correct, time_taken_seconds):

    update avg_time_ratio (see Section 8)

    append is_correct to last_3_results (keep only last 3)

    if level == "basic":
        if is_correct: streak += 1
        else: streak = 0
        if 2 out of last 3 correct: promote to "medium", streak = 0

    elif level == "medium":
        if is_correct: streak += 1
        else: streak = 0
        if streak >= 3 correct IN A ROW: promote to "advanced", streak = 0
        if 2 out of last 3 wrong: demote to "basic", streak = 0

    elif level == "advanced":
        if last 2 answers both wrong: demote to "medium"
        # otherwise stays; periodically receives a probe question to confirm retention
```

Notes:
- Demotion uses a rolling window (2 out of last 3), not a single wrong answer — a single careless mistake should not undo real progress.
- This logic must live in one shared module, not duplicated across the API — future changes to thresholds should only require editing one place.

---

## 8. Time / Pace Tracking (runs alongside the state machine, independently)

```
time_ratio = time_taken_seconds / expected_time_seconds(difficulty)

update avg_time_ratio as a running average per (student, topic)

if avg_time_ratio <= 1.2: pace_flag = "fast"
if avg_time_ratio > 1.2: pace_flag = "slow"
```

- `pace_flag` does NOT affect `level` — it's a second, independent signal.
- A student can be `level: advanced, pace_flag: slow` — technically correct but not exam-ready on speed. This is a genuinely useful distinction to surface to teachers.
- Only counted when the answer is correct (an incorrect fast guess isn't "fast mastery," it's noise — exclude incorrect attempts from the time-ratio average).

## 9. Adaptive Paper Generator (Papers 4+)

```
for each topic:
    num_questions = round(importance(topic) / 100 × total_paper_length)
    level = student_topic_state[student][topic].level
    pool = questions WHERE topic_id = topic AND difficulty = level
    selected = sample(pool, num_questions)

    if student_topic_state[student][topic].pace_flag == "slow":
        # swap in 1-2 additional questions from this topic as timed practice
        # this does not change num_questions logic above, it's a supplementary drill

    occasionally include 1 probe question from adjacent difficulty
    (to test for promotion out of "advanced" plateau or catch silent regression)
```

Topic proportions (importance) are never modified per-student — only which difficulty pool is sampled from, plus optional pace-driven supplements.

---

## 10. Feedback Loop / Reporting

Two fingerprinting layers, both derived from `test_attempts`:

- **Mistake fingerprinting**: when wrong, log which `wrong_option_tags` category was hit → builds a misconception profile per student per topic over time
- **Time fingerprinting**: `pace_flag` per topic → tells us "knows it" vs. "knows it fast enough"

Both feed the institute-facing dashboard (batch-level heatmap of weak topics + slow topics) and the student-facing report.

---

## 11. v2 Roadmap (not built now)

Once enough real student attempt data exists, replace the hardcoded state machine with **Bayesian Knowledge Tracing**, which tracks a probability of mastery per topic instead of a hard label, updating after every attempt. Same inputs (correctness, time), smarter output, still explainable. Model Support owns researching this now so we're ready to build it when the data justifies it.
